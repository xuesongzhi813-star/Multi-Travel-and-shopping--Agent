## 数据和版本

FAQ 原文、公开来源及不可变版本放入 MySQL，采用现有专用项目账号和项目库。每一版本有稳定标识及内容摘要值。同一版本、同一内容重放成功。若同一版本 ID 携带不同内容则拒绝，修订通过新版本发布。导入前验证来源字段、唯一键、语言、类别及可解析格式。在同一事务提交完整语料和版本记录。

沿用正式应用和现有数据模块。知识索引构建通过独立本机 CLI 执行，切分复用现有合适的解析或切分函数。启动聊天服务不等待导入或重建 FAQ。P8 在实际 Qdrant 为每次构建创建独立的 payload 集合，保存可确定重建的切片、文档 ID、来源、类别、语言、版本及内容摘要。先按关键词字段建 payload 索引，并按文档 ID 实测读取。P9 从相同 MySQL 原文构建向量版，接入混检、精排、Redis 缓存和聊天 FAQ 路由。P8 发布与验收无需付费模型或外部 API 凭据。 [Qdrant Collections](https://qdrant.tech/documentation/manage-data/collections/)

## 发布、故障和回退

CLI 提供导入、构建、激活、状态与回退，以及从当前版本按文档 ID 读取证据。构建时从单一 MySQL 版本读取原文，创建全新集合，用稳定切片 ID 写入并等待完成。验证全部条数、切片摘要、来源和指定文档读回后才把该集合标记为可发布。

激活在 MySQL 短事务中校验已验证构建，并根据调用方提供的预期指针修订号执行更新。首次发布前修订号为 0，首次发布、切换和回退均单调递增。指针绑定知识版本与具体集合，每次读只获取一次。构建中断、写入失败或校验失败时旧指针与旧集合仍可查询。并发激活时过期的预期修订号失败，回退到同一个旧集合也不会让旧修订号重新生效。回退需要明确指定先前已发布且仍通过读回校验的构建 ID。活跃集合与先前发布的集合保留，CLI 本阶段不自动删除集合。

## 验收

- 在 MySQL 现有授权项目库里用随机表前缀，搭配随机 Qdrant 集合名导入首批数据，核对来源、日期、分类、原文和切片可重建。断言重复导入和同版本冲突的行为。测试账号无需改授权或创建数据库。
- 激活旧构建并成功读取，然后注入新版写入中断或验证失败，旧版仍可读取。重建并激活新版后验证证据版本一致，再做一次回退。并发激活不能让未验证或过期构建覆盖当前版本。
- 通过正式 P6 酒店查询获取新增合成库存。新增酒店选项可带目录 URL、核对日期和演示标记，网页显示对应来源。原有两个酒店遗漏新字段时保持现有 JSON 和网页行为，该来源字段不参与 P7 报价或订单授权。通过真实 PostgreSQL 验证跨夜段和无房。模拟 P7 预订扣减后重新导入，库存、订单与回执保持一致。
- 复跑 P7 预订和根、角色环境回归。测试只清理本次创建的临时对象，不在真实酒店下单。
