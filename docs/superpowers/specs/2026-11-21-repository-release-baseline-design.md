## 目标

为[新 GitHub 仓库](https://github.com/xuesongzhi813-star/Multi-Travel-and-shopping--Agent) 准备一个独立、可审查的本地起始提交。新仓库已确认为公开空仓库。当前工作区的 `origin` 指向原项目，基线提交为 `a30f964`。

P0 交付本地发布候选及验收记录。新合成用户、行程和库存由 P2 交付，FAQ 和酒店演示资料按 P8 交付。公开推送另行核对上游许可、候选内容及目标仓库。

## 方案

用户已选择独立起始提交。把审查通过的项目文件复制到隔离目录，新建 Git 仓库并创建一个无父提交的候选。原工作区保留旧文件、分支和历史，便于查阅及运行旧环境。候选文件清单保留原项目来源和基线信息。

另一种方案是逐提交清理旧历史，再导入新仓库。该方案能保留原有演进记录，但至少有四个旧提交触及会话、日志或数据库路径，需逐提交及逐引用复核。用户已选择前一种方案。

## 候选内容

- 按文件清单审查源码、依赖锁文件、容器与项目配置、文档和资产。核对二进制资料的用途和来源。发布设计文档如包含旧目录链接，随候选检查链接指向。
- 排除旧会话 JSON、运行日志、SQLite 文件、数据库备份、旧数据 SQL、未核验的 FAQ 样本和 Python 字节码。从候选中一并移出依赖旧 SQL 和旧数据的 `setup_database.py`，保留原工作区的版本供参考。以后由新阶段提交可重复生成的种子数据和初始化方式。
- 添加版本化的忽略规则，覆盖 `.env` 及本地变体、凭据文件、会话目录、日志、数据库产物、Python 缓存、虚拟环境和构建产物。明确允许无真实值的配置示例和经核验的合成种子文件。
- 留痕仅记录路径、命令结果、计数和处理决定。密钥、私人会话正文和数据库内容留在发布候选之外。上游 GitHub 未显示许可证，发布前需核实再发布授权。

## 验收

1. 在隔离仓库中确认候选历史只有一个提交，该提交无父节点且没有继承原仓库的分支或标签。
2. 检查候选提交的实际文件树及文件内容。验证禁止的文件类别均未进入提交，密钥特征扫描的输出只含路径或计数。未经核验的文件数为零，发现项应从候选中排除后复查。
3. 使用代表性路径验证忽略规则。真实环境文件、日志、会话和数据库产物应匹配忽略规则，无密钥的配置示例及将来的合成种子文件应能正常跟踪。
4. 在候选目录检查依赖锁，构建主项目 wheel。检查 wheel 也未带入候选排除的数据。现有应用仍引用旧 SQLite，真实服务联调和数据替换按后续阶段验收。
5. 比较操作前后的原工作区状态，确认原仓库的分支、HEAD、远程配置和既有跟踪文件未被修改。记录候选目录、提交标识和验收结果，供 P0 评审。
