# P9 旅行 FAQ 混合检索、精排与缓存

2026-11-24 · 规格已批准 · 开发基线 `p8-faq-hotel-data` / `f0764e8`

## 交付范围

用户可在正式聊天入口独立询问公共旅行政策，查看证据来源和适用条件。航班与酒店角色也能在行程对话中按需调用同一个只读 FAQ 工具，例如说明行李延误处理或演示住宿的政策适用条件。用户已选择在 P9 接入两个角色。FAQ 不读取私人行程或订单，不决定预订或写入权限。P10 的跨会话偏好与历史及 P11 的完整质量评估另行验收。

## 索引与发布

拟沿用 P8 的版本、构建与发布指针。`scripts/manage_faq.py` 增加显式的混检构建模式，从同一份不可变 MySQL 原文和既有分块规则创建新 Qdrant 集合。新集合保存来源、作用范围、切片、`version_id`、类别和语言，使用 `BAAI/bge-m3` 稠密向量及 Qdrant 原生 BM25 全文索引。中文索引和查询均使用 `multilingual` tokenizer。构建记录保存索引能力和模型标识。发布前核对载荷完整性、向量能力、过滤和代表性查询。失败后旧发布指针保持有效。

对已有集合原地补向量，无法先完成新索引验收再切换。单独维护检索发布指针会使同一次 FAQ 请求可能读到两个生效版本。拟采用新集合加单指针切换，继续用修订号防止并发覆盖。历史 P8 集合仍支持按文档 ID 查证据。若回退到 P8 集合，检索返回可区分的未发布混检索引状态，聊天说明政策检索暂不可用。

## 检索与缓存

每次请求读取一次生效指针并使用同一快照完成查询。按类别、语言和版本过滤两路候选，Dense 与 BM25 各取 Top-100。Qdrant 使用 RRF `k=60`，融合后取前 40 条去重，交给 `BAAI/bge-reranker-v2-m3` 精排至多 10 条。选至多 6 段带有效引用的证据供答复使用。精排超时或响应无效时，返回 RRF 证据并标记降级。没有足够证据时，答复说明无法核实。相似度阈值与引用策略使用验收样本校准，实际阈值纳入计划。

Redis 仅缓存经校验的公共 FAQ 证据。键包含发布修订号、构建 ID、规范化问题摘要、过滤条件和检索配置。发布切换或回退后即使版本内容相同也会重取。缓存 TTL 拟定 15 分钟。Redis 不可用时走限时直查。精排降级结果暂不缓存，以便服务恢复后立即重新精排。索引和查询的模型配置须匹配。

## 正式聊天与角色调用

沿用 `web_app.app.runtime:app`、已认证的消息路由和父图输入防护。待确认的旧审批仍沿用 P7 的阻塞语义。独立 FAQ 回复包含答复、证据和降级状态，且不消耗进行中的酒店澄清。会话投影允许历史结果缺少 FAQ 字段。现有浏览器聊天界面展示独立问答及两个角色回复的来源链接、适用条件和降级提示，刷新后可从同一会话投影恢复展示。

航班和酒店角色通过既有工具注册和统一执行器调用 `search_public_faq`。执行器重新验证角色权限和入参，工具只接收有限长度的通用政策问题及可选类别、语言。发给外部嵌入或精排服务的材料限定为公开政策查询及公开候选切片。混有订单号、证件、联系方式、姓名等私人信息的问题，先隔离为可验证的通用子问，无法安全分离时请用户重述。工具审计保留关联标识、状态、耗时和安全摘要。查询原文、会话内容和凭据不得进入审计或缓存键明文。FAQ 故障不会改变航班事实、住宿库存或审批结果。引用从已验证的证据映射取得，角色输出不自行指定来源 URL。

正式航班和酒店 Web worker 当前使用可重复的离线角色流程。P9 通过现有父图回调与 worker 协议传入已筛选的政策子问，扩展角色的受控工具调用序列及证据结果。酒店仍需取得独立的库存回执，航班仍需取得自有行程与机场证据。工具按用例每轮至多调用一次 FAQ，共享角色剩余时限。P9 的真实供应商验收只启用硅基流动嵌入和精排，正式角色验收保持现有脚本模型。

混合业务与政策的消息先走现有输入防护及待审批限制。通过后，若政策部分无法安全拆出，跳过外部检索并请用户重述政策问题。符合原规则的航班和库存查询照常处理。审批、确认和写入仍按既有显式动作触发，政策子问不能成为触发条件。

## 验收

- 真实 MySQL、Qdrant 和 Redis 配合确定性模型替身验证双路 Top-100、`k=60`、中文召回、相同过滤、构建失败、回退、缓存版本隔离以及 Redis 和精排故障。自动化回归不调用付费模型。
- 经正式 HTTP 验证独立问答、航班角色问答、酒店角色问答、引用、无证据、降级和私人信息拦截。用真实浏览器验证引用链接、降级提示和刷新恢复。回归会话归属、酒店澄清、预订审批及旧版本回退。
- 真实硅基流动验收使用临时索引和合成公共问题，拟上限 10 次请求、单次 10 秒、自动重试 0 次。覆盖目录嵌入、查询嵌入和返回可映射证据的精排。样本至少覆盖中文同义问法、政策适用范围和无答案。真实验证由用户批准执行范围后单独显式运行。
- P9 分支拟从 `f0764e8` 建立，可在 P8 合并前开发。正式仓库的主分支及发布由单独的集成决定处理。
