# P6 · 航班到酒店交接

状态：已审批。基于正式仓库 `main` 的 `dcbd6ba`，沿用总体设计 ADR-01 B。

## 用户体验与范围

用户在已登录的会话中提出落地住宿需求。父图验证本人航班，以到达地当地日期作为入住日期。缺少晚数时，系统问「您打算住几晚？」并等待当前会话的下一轮。用户补充晚数后，系统查询现有合成库存，展示满足整段住宿的酒店、房型和演示总价。酒店预订和网页确认由 P7 交付。

P6 提议沿用 `POST /api/threads/{thread_id}/messages` 与会话状态查询。通过现有网页消息框支持带航班编号的酒店请求，例如「帮我找 DEMO-A1 落地后的酒店」，以及澄清回复「住 1 晚」。首版覆盖这种有限的可重复用语，晚数为 1–14 的整数。晚于入住日的 ISO 退房日期也可换算为晚数，两项冲突时询问确认。航班编号和晚数同时缺失时先问航班，保留用户已明确给出的字段。等待航班时可仅回复一个编号，等待晚数时可回复「住 2 晚」或「2」。这些短回复只有在会话正等待相应字段时才续查。无关消息保持普通会话行为，不能触发酒店工具。

## 集成方式

采用父图节点协调交接，在同一个角色 Python 环境复用现有子进程和航班角色，增加独立的酒店 `create_agent`。现有航班工具 HTTP 入口继续用于单独查航班。由该入口编排酒店会产生另一套会话状态，由一个角色同时持有航班和酒店工具则扩大权限。当前方案保留父图为控制点和角色权限隔离。

1. 聊天入口认证、校验会话归属并取得会话锁。父图先运行现有输入防护，再进入航班或澄清分支，拒绝分支不访问角色工具。
2. 父图复用服务端本人航班查询和角色子进程。仅接收结构化、已核验且与所选航班一致的航班编号、到达机场、当地日期、时区及工具出处。由受控机场目录得到城市。空结果、未知城市或不支持的酒店区域均有明确回复。对不存在和非本人航班给出相同的不可用结果。
3. 缺少晚数时，父图将待补齐的请求和最小已核验交接事实写入同一会话检查点。补充回复需对应当前待办，查询前重核本人航班和日期。新航班请求替换旧待办，完成后清除待办。明确取消时清除待办，普通无关消息和被防护拒绝的内容不触发续查。保留既有 JSON 检查点和旧会话的兼容性。
4. 酒店角色只接收城市、时区、入住和退房日期、用户明确提供且本阶段支持的住宿条件。首版支持酒店区域和房型，可不填。角色看不到航班编号、航班对话、原始用户历史、航班工具或机场工具。身份、会话和运行标识由宿主提供给执行器及审计，无需放进模型上下文。父图保留航班来源用于追溯。
5. 酒店角色通过统一执行器调用唯一的只读库存工具。工具使用宿主绑定的已核验查询条件，拒绝模型提出的冲突参数。演示酒店表暂无城市列，当前数据只在已核对的 Zürich 目录项下查询。其他城市返回未覆盖，避免误用苏黎世库存。查询以当地入住日期（含）到退房日期（不含）为窗口，只返回每晚均可用的同一酒店和房型，按币种与演示总价稳定排序并限制返回量，不混算币种。展示结果直接取自通过校验的工具回执。

## 状态与失败处理

普通与拒绝消息维持 `recorded` 和 `rejected`。P6 增加可区分的查询结果，包括 `needs_clarification`、`hotel_results`、`no_availability` 和 `unavailable`，附简短回复。酒店结果仅投影酒店、区域、房型、日期、演示总价和币种。待补齐字段保留在内部状态。读取同一会话状态可恢复最新回复和展示结果。消息响应中的既有字段保留，现有航班及机场入口行为保持兼容。

角色进程失败或超时给出可识别的不可用结果，提示用户重新发送完整酒店请求。本轮已知失败时结束该待办，不自动重试整轮。若请求因断线未提交检查点，下一轮依照最近一次已提交状态处理。角色与图共享明确的截止时间，角色工作预算纳入现有会话锁事务的时间边界。测试覆盖超时、取消、锁释放及后续轮次。默认用脚本模型和真实本机依赖验证，付费调用需另行授权。P6 不向库存、订单或审批表执行写操作。

## 验收

- 以实际本地 HTTP 入口验收。已登录的 demo-a 发送 `DEMO-A1` 酒店请求后先收到晚数追问，此时没有酒店工具调用。重启应用后在原会话补充「住 1 晚」，入住日期为苏黎世当地 `2026-12-15`，退房为 `2026-12-16`，相应库存能够查出。跨用户重新读取和续答均被拒绝。
- 测试使用临时 schema 构造多晚库存，覆盖中间缺一晚、房型变化、库存为零、币种不一致及总价计算。生产演示种子保持现有范围。
- 覆盖缺航班编号、无效或矛盾晚数、无关回复、切换航班、取消、不支持的城市、模型超时和跨用户查询。验证拒绝与空结果可区分。
- 捕获脚本模型可见的消息和工具清单，确认酒店角色上下文遵守隔离要求。验证航班与酒店调用都可通过审计追溯，且没有预订或库存扣减。
- 复跑 P5 两套测试，记录正式启动和真实 HTTP 验收。无需新启动入口或切换锁定依赖；计划阶段逐项核对所用接口及锁定版本。
